Research

Prototype reasoning · Evidential uncertainty

Interpretable visual diagnosis with calibrated evidence

A classifier whose decision path runs through learned class prototypes, so the evidence for a prediction is structural rather than reconstructed after the fact, paired with a Dirichlet evidential head that reports how much evidence supports each class. Built the full pipeline — spectral band gating, prototype reasoning layer, evidential head — and evaluated it across six crops and seventeen disease classes with grouped cross-validation.

What it taught me. One run reached near-perfect accuracy while its confidence was no better calibrated than a coin flip. Working back from the reported accuracy and calibration error put mean confidence near 0.5 — the model could not be more certain than that about anything. The cause was not the architecture but the temperature mapping prototype similarity to probability: below one, the formula flattened the distribution instead of sharpening it, structurally capping the maximum probability. Correcting a single setting recovered folds that had been stuck at chance. Since then I read the confidence distribution before the accuracy table.

Experiment design · Doubting my own method

Ablation as a way to look for my own mistakes

After an earlier manuscript was rejected for methodological overlap, I redesigned the method as four modules — frequency decoupling, mutual self-distillation, spectral consistency regularization, and an evidential head — each behind an independent flag, so that ablation was possible by construction rather than as an afterthought.

I also traced a failure where the evidential learning signal decayed inversely with the number of classes, so training barely moved past thirty-odd classes. Three candidate fixes were tested separately; only rescaling the signal worked, and the other two did nothing on their own.

What it taught me. Two results were uncomfortable and both changed the paper. Ablation showed regions where removing a module matched or beat the full model. And the claim that my mechanism prevented training collapse looked like it might be an artifact of the early-stopping setting — so I ran a control varying only that setting, and confirmed it alone could manufacture a “collapse.” Experiment design is for giving a hypothesis a chance to fail, not for confirming it.

Label efficiency · Uncertainty

Learning visual representations with fewer labels

In field diagnosis not every sample can be inspected. This work fuses six evidence sources with different strengths and failure modes, attaches distribution-free guarantees to the fused prediction, and uses those guarantees to decide which samples a human should check first.

What it taught me. Uncertainty means something only as an input to a decision. “This prediction is uncertain” is not information; “inspect this sample first” is.

Instance-adaptive fusion · Negative result

Measuring what an adaptive fusion layer could add, before building it

Prediction pipelines that draw on several sources often add a layer that decides, per record, which source to trust. Before building that layer, I measured the ceiling on what it could possibly contribute, using an oracle upper bound. The expected gain was not statistically significant, and I reported it as such.

Why I keep it here. Not claiming an improvement you have not measured is the starting point for working on trustworthy models, not an exception to it.

Multimodal · Capstone

Review helpfulness prediction (PRIS-RHP)

Predicting review helpfulness from review text together with reviewer metadata and interaction signals, on a large-scale review corpus. Signals that text representations alone missed turned out to sit in the metadata. Received the Excellence Award at the Hansung University Capstone Design showcase.

What it taught me. Which signal actually contributes is rarely what intuition says. This is where I first needed an ablation, and it has been standard practice for me since.

Industry collaboration · Pre-capstone

DB Bridge — natural-language data extraction

A retrieval-augmented system that extracts requested fields from natural-language questions. Output shifted substantially with prompt design alone, which was my first encounter with how wide the band of behaviour is that you can change without touching the model.

Research Tooling

Built because the research needed them.

  • Parallel runner — distributes tasks across GPUs, cutting experiment turnaround roughly fourfold against sequential runs.
  • Probe-gated chaining — a short trial run must pass before the full run starts, so a misconfigured setting no longer costs a long job.
  • Result aggregation and status board — collects scattered run outputs into tables and shows what is currently running at a glance.
  • Config logging — every run records its own configuration, added after a folder with the same name was silently reused under different settings.
